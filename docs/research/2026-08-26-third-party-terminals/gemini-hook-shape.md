## Verdict

**Does the heartbeat's stdout parse untranslated? YES.** Gemini's `getAdditionalContext()` (`packages/core/src/hooks/types.ts:263-277`) only checks for the presence of the key `hookSpecificOutput.additionalContext` — it never inspects the `hookEventName` value inside that object, so the heartbeat's `"hookEventName": "PostToolUse"` (a Claude-shaped string, not Gemini's `"AfterTool"`) is silently ignored and the `additionalContext` string is appended to `toolResult.llmContent` exactly as if a native Gemini hook had produced it (`packages/core/src/core/coreToolHookTriggers.ts:216-236`). Item 2 was the cheapest inversion point per the brief's premise, and it did **not** invert: the output side of the envelope is translation-free.

**Does stdin need translation?**
- Cursor/session id: NO — Gemini's field is named `session_id` and `cwd` (`types.ts:141-147`), identical names to what the heartbeat already reads (`_field(payload, "agent_id", "session_id")` at `swarm-heartbeat.sh:339`, `payload.get("cwd")` at `:779/785`). No field-name shim needed here.
- Enrol/claim legs (tool names): YES — Gemini's tool names for shell/write/edit/read are `run_shell_command`/`write_file`/`replace`/`read_file`, not Claude's `Bash`/`Write`/`Edit`/`Read`. The heartbeat's `tool_name in FILE_TOOLS` check (`swarm-heartbeat.sh:642,772`) and its `tool_name == "Bash"` branch (`:783`) will silently miss every Gemini AfterTool beat, because Gemini's tool names never match those literals. This is a false-negative failure mode, not a crash: the doc-enrol leg and the Bash write-shape detection both go quietly dark under Gemini, matching neither `FILE_TOOLS` nor `"Bash"`/`"apply_patch"`.

**Smallest shim shape:** a thin translation layer sitting only in front of the tool-name comparisons — a dict mapping Gemini's tool names to the heartbeat's existing vocabulary (`run_shell_command→Bash`, `write_file/replace→Write/Edit` for the `FILE_TOOLS` membership test, `read_file` added as a no-op branch since no read leg exists today), applied to `payload["tool_name"]` immediately after `json.loads(payload_raw)` and before the existing `tool_name in FILE_TOOLS` / `tool_name == "Bash"` checks; everything downstream (field names, stdin session/cwd extraction, and the entire stdout emission path) needs no change. Gemini itself ships this exact map in `packages/cli/src/commands/hooks/migrate.ts:37-45`, so the shim can literally invert that table rather than deriving its own.
